# 13. 常见问题 FAQ

## ❓ Odin1 Lite 支持哪些系统？

**回答：**

| Ubuntu 版本 | 支持的 ROS 版本 |
|:--|:--|
| 20.04 | ROS1 Noetic |
| 22.04 | ROS2 Humble |
| 24.04 | ROS2 Jazzy |

支持 x86 与 ARM（Jetson）架构。

---

## ❓ 设备上电后无法发现或无法 ping 通？

**回答：**

1. 确认设备指示灯是否常亮（供电正常）。
2. 确认 PC 网卡 IP 与设备处于 **同一网段**：
   - 设备默认 IP：`192.168.1.251`
   - PC 建议设置：`192.168.1.x/24`（避免与设备 `.251` 冲突）
3. 通过 `ifconfig` 检查 IP 是否真正生效，必要时**禁用再启用网卡**。
4. 检查防火墙是否阻断 UDP 广播（端口 60000–60010）。
5. 设备发现、网卡选择和 UDP 端口均由 SDK 自动处理，无需也无法通过 launch 配置 `device_ip`。

---

## ❓ 相机没有固定 IP，如何通过 DHCP 自动分配？

**回答：** 使用仓库提供的 `script/start_dhcp.sh` 脚本启动 udhcpd 服务器即可：

1. 安装 udhcpd：`sudo apt install udhcpd`
2. 按 `script/my_dhcp.conf` 修改监听网卡、IP 池和网关。
3. 启动 DHCP：`sudo ./script/start_dhcp.sh /path/to/my_dhcp.conf`
4. 查看租约文件 `/var/lib/misc/udhcpd.leases` 确认相机已拿到 IP。

## ❓ 多台 PC 同时连接同一局域网，话题数据相互干扰？

**回答：**

- **ROS2**：为每台 PC 设置不同 `ROS_DOMAIN_ID`

  ```bash
  echo $ROS_DOMAIN_ID            # 查看当前值（空白或 0 表示共享）
  export ROS_DOMAIN_ID=1         # 1–99；0 为共享
  ```

- **ROS1**：限制 master 仅本机可见，或更换端口

  ```bash
  # 推荐
  export ROS_LOCALHOST_ONLY=1

  # 或：使用其他端口
  roscore -p 11312
  export ROS_MASTER_URI=http://localhost:11312
  ```

> 上述命令仅对当前终端有效，如需永久生效请加入 `~/.bashrc`。

## ❓ 建图 / 重定位漂移或丢包严重？

**回答：**

高码率传感器数据可能撑爆内核网络接收缓冲区，导致 UDP 丢包，进而影响 SLAM 和重定位效果。运行驱动前请放大缓冲区并设置独立的 `ROS_DOMAIN_ID`：

```bash
# 放大内核接收缓冲区
sudo sysctl -w net.core.rmem_max=16777216
sudo sysctl -w net.core.rmem_default=8388608
sudo sysctl -w net.core.netdev_max_backlog=50000

# 将当前 PC 与同一局域网内的其他 ROS2 主机隔离
export ROS_DOMAIN_ID=1   # 1–99；不同 PC 使用不同 ID
```

如需永久生效，将 `sysctl` 设置写入 `/etc/sysctl.conf`（或 `/etc/sysctl.d/` 下的文件），并将 `export ROS_DOMAIN_ID=1` 加入 `~/.bashrc`。

## ❓ Sensor Mode 应该选择 High Peak 还是 Low Peak？

**回答：**

| 模式 | 推荐场景 | 说明 |
|:-:|:--|:--|
| 0 / HDR | 通用 | 自动平衡远近 |
| 1 / High Peak（长帧）| **户外** | 抗强光好，近距精度略低 |
| 2 / Low Peak（短帧）| **室内** | 优化近距与小空间噪点，受强光影响大 |
| 3 / Adaptive | 通用 | 自适应切换 |

切换方式参见 [7. Odin1 Lite 快速启动（Ubuntu）§7.9](7.%20Odin1Lite%20Quick%20start%20for%20ubuntu#79-长短帧sensor-mode切换)。

## ❓ 编译失败提示 `ODIN SDK not found`？

**回答：** 通常是首次编译没有进入 `module/sdk_api` 子模块。请按下列任一方式处理：

1. 使用驱动包内提供的 `script/build_ros1.sh` / `script/build_ros2.sh`（脚本会自动编译并安装 SDK）。
2. 手动初始化 SDK 子模块：`git submodule update --init module/sdk_api`。
3. 如果 SDK 已经预装到自定义路径，设置环境变量：`export ODIN_SDK_PREFIX=/path/to/install`。

---

## ❓ 编译时整机卡顿、内存占满甚至 GUI 无响应？

**回答：** 驱动中部分节点（如 `post_process_node`）单编译单元需要 1.0–1.6 GB 内存，默认并发可能撑爆小内存平台。`build_ros1.sh` / `build_ros2.sh` 已按内存自动限制并发（约每任务 2 GB），也可手动指定：

```bash
# 限制并发数
ODIN_BUILD_JOBS=2 ./src/ros_driver/script/build_ros2.sh

# 或用 MAKEFLAGS 完全控制
MAKEFLAGS="-j2 -l3" ./src/ros_driver/script/build_ros2.sh
```

8 GB 及以下设备建议 `-j1` 或 `-j2`，必要时用 cgroup 保护 GUI：

```bash
systemd-run --user --scope -p MemoryHigh=5G -p CPUWeight=20 \
  ./src/ros_driver/script/build_ros2.sh
```

## ❓ RViz 提示 TF 变换失败，点云无法显示？

**回答：** 设备原始 TF 发布频率较低时，点云时间戳可能落在最新 TF 之后，导致 tf2 无法插值。启动驱动时启用 TF 定时重发：

```bash
ros2 launch odin_ros_driver_rev1 odin1Lite.launch.py tf_publish_rate:=50
```

推荐设置为 50–200 Hz；设为 `0` 时禁用定时重发，保持设备原始频率。

---

## ❓ ROS2 录制 rosbag 时高频话题丢包？

**回答：** 使用驱动提供的 QoS 覆盖配置，以可靠模式录制：

```bash
ros2 bag record -a \
  --qos-profile-overrides-path ~/catkin_ws/src/ros_driver/config/rosbag2_qos.yaml
```

ROS1 使用 TCPROS，直接使用 `rosbag record -a` 即可；磁盘 I/O 较慢时可增加 `--buffsize`。

---

## ❓ 用 `ros2 topic hz` 看 `cloud_raw` 帧率很低，是驱动发布频率不够吗？

**回答：** 不一定是驱动发布频率低。有客户反馈用 `ros2 topic hz` 查看 `cloud_raw` 时，打印出来的频率明显偏低；这通常是 `ros2 topic hz` 的测量方式导致，尤其是在重定位（Relocation）开始后，算法会向上发送较大的点云数据，`ros2 topic hz` 基于 Python 订阅端计数，对 `PointCloud2` 这类大消息容易受反序列化与传输开销影响，导致显示的帧率低于实际发布帧率。

要验证真实帧率，建议改用**录包后统计**：

```bash
ros2 bag record /manifold/device0/cloud/raw \
  --qos-profile-overrides-path ~/catkin_ws/src/odin_ros_driver/config/rosbag2_qos.yaml
```

录制结束后用 `ros2 bag info <bag>` 查看 `Message count` 和 `Duration`，按 `message_count / duration` 计算出的帧率更准确。

> 如需实时观测，可启动驱动自带的 `diag_subscriber_node`（C++ 订阅端），它对 `PointCloud2` 等大消息的帧率统计比 `ros2 topic hz` 更准确。

## ❓ `post_process_node` 发布第一帧图像时崩溃？

**回答：** 这通常是系统安装了多个 OpenCV，导致驱动链接的 OpenCV 与 ROS apt 版 `cv_bridge` 不一致。请在当前工作空间重新编译 `vision_opencv` 中的 `cv_bridge`，使其与系统 OpenCV 使用相同版本，然后再编译驱动：

```bash
cd ~/catkin_ws/src
git clone -b $ROS_DISTRO https://github.com/ros-perception/vision_opencv.git
cd ~/catkin_ws
colcon build --packages-select cv_bridge
source install/setup.bash
./src/ros_driver/script/build_ros2.sh
```

ROS1 请使用 `catkin_make -DCATKIN_WHITELIST_PACKAGES="cv_bridge"` 编译 `cv_bridge`。可通过 `ldd <post_process_node路径> | grep -iE 'cv_bridge|opencv_core'` 确认只加载同一版本的 OpenCV。

## ❓ 节点崩溃后如何用 GDB 调试？

**回答：** 先用 Debug 模式编译，再用 `launch-prefix` 启动 GDB：

```bash
# Debug 编译
./src/ros_driver/script/build_ros2.sh --cmake-args -DCMAKE_BUILD_TYPE=Debug

# 交互式 GDB
ros2 launch odin_ros_driver_rev1 odin1Lite.launch.py --launch-prefix "gdb -ex run --args"

# 非交互式（适合 SSH / 嵌入式）
ros2 launch odin_ros_driver_rev1 odin1Lite.launch.py \
  --launch-prefix "gdb -batch -ex run -ex 'bt full' --args"

# 仅调试单个节点
ros2 launch odin_ros_driver_rev1 odin1Lite.launch.py \
  --launch-prefix "gdb -ex run --args" --launch-prefix-filter post_process_node
```

崩溃后在 GDB 中执行 `bt full`、`thread apply all bt` 查看调用栈。若调用栈全是 `??`，说明未带调试符号，需重新 Debug 编译。

## ❓ 如何验证硬件 JPEG 解码已实际生效？

**回答：** 驱动启动日志仅说明编译期解码路径，不能作为硬解已生效的依据。建议同时验证硬件中断持续增长、`post_process_node` 持有硬解设备节点、且 CPU 占用较低：

```bash
# RK3588
watch -n 1 'grep -E "jpegd|vdpu|rkvdec" /proc/interrupts'
sudo lsof /dev/mpp_service | grep post_process

# Jetson
sudo tegrastats --interval 500 | grep -E "NVJPG"
sudo lsof /dev/nvhost-nvjpg | grep post_process
```

## ❓ Jetson 上硬件 JPEG 解码 fallback 到软解时崩溃？

**回答：** Jetson R36/JetPack 6 上，当硬件解码失败并 fallback 到软件解码时，可能因 `libnvjpeg.so` 与 OpenCV 使用的 `libjpeg-turbo` 符号冲突导致 `free()` 野指针崩溃。若需稳定使用软件解码，请重新编译：

```bash
# 仅 ROS2 示例；ROS1 用 build_ros1.sh 并加 -DJPEG_PREFER_SOFTWARE_DECODER=ON
colcon build --cmake-args -DJPEG_PREFER_SOFTWARE_DECODER=ON
```

默认 `JPEG_PREFER_SOFTWARE_DECODER=OFF` 使用硬件解码；仅在需要纯软解或遇到 fallback 崩溃时开启。

## ❓ 如何远程升级固件？

**回答：** 浏览器访问 `http://192.168.1.251:8080` → **Update** 页面拖入固件包，系统将自动安装并重启。详见 [8. 固件升级](8.%20Firmware%20Upgrade)。

## ❓ 标定文件 / 重定位地图 / 设备日志怎么导出？

**回答：** 全部可在 HTTP Dashboard 完成：

- 标定文件管理：上传 / 下载 `camera_calib_<SN>.yaml`
- 地图文件下载：导出重定位地图
- 系统日志下载：打包成 `.tar.gz`
- 遥测数据录制：导出 CSV
