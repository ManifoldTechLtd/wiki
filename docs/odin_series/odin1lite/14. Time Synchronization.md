# 14. PTP 时间同步

Odin1 Lite 支持基于 **PTP（Precision Time Protocol，IEEE 1588）** 的高精度时间同步，可将设备系统时钟与上位机（Host）时钟同步到**毫秒级以内**，使 LiDAR、相机、IMU 等传感器数据的硬件时间戳与主机时钟处于同一时间基准，满足多传感器融合、多机协同等对时间一致性要求较高的应用场景。

> Odin1 Lite 默认使用系统时钟（SysTick）作为传感器数据时间戳来源。未部署 PTP 环境时无需任何配置。

## 14.1 PTP 协议原理

### 14.1.1 协议概述

PTP（IEEE 1588）是一种面向局域网的高精度时钟同步协议，与 NTP（毫秒~十毫秒级）相比，PTP 通过**硬件时间戳**（Hardware Timestamping）将同步精度提升至**亚微秒级**，广泛应用于工业自动化、电信、车载与机器人领域。

PTP 采用**主从（Master-Slave）架构**：

- **主时钟（Grandmaster / GM）**：网络中的时间源，通常为上位机或专用时钟服务器；
- **从时钟（Slave）**：与主时钟对齐的设备，Odin1 Lite 在同步网络中作为从时钟；
- **边界时钟（Boundary Clock, BC）** / **透明时钟（Transparent Clock, TC）**：中间网络设备（如 PTP 交换机），逐跳修正链路时延，避免多级转发引入的累积误差。

### 14.1.2 同步机制（Delay Request/Response 机制）

主从时钟之间通过四类报文完成时钟偏移与链路时延的测量：

```text
主时钟（Master）                         从时钟（Slave）
      │                                        │
      │ ── Sync（t1 硬件打戳） ──────────────▶ │ t2
      │ ── Follow_Up（携带 t1） ─────────────▶ │
      │                                        │
      │ ◀───────────── Delay_Req（t3 打戳）── │ t3
      │ ◀──────── Delay_Resp（携带 t4）────── │ t4
      │                                        │
  偏移：offset = [(t2-t1) - (t4-t3)] / 2
  链路时延：delay = [(t2-t1) + (t4-t3)] / 2
```

1. 主时钟周期性广播 `Sync` 报文，并在报文经过网卡时由 **PHY/MAC 硬件打上精确时间戳**（t1）；从时钟记录接收时间戳（t2）；
2. `Follow_Up` 报文将 t1 传递给从时钟；
3. 从时钟发送 `Delay_Req`（打戳 t3），主时钟回复 `Delay_Resp`（携带接收时间戳 t4）；
4. 从时钟根据上述公式解算时钟偏移（offset）与链路时延（delay），并逐步**驯服（discipline）**本地时钟。

关键精度保障在于 **t1–t4 均由硬件产生**，消除了协议栈软件处理带来的不确定时延（抖动可达数十微秒），这也是 PTP 相对软件 NTP 方案的核心优势。

### 14.1.3 传输协议：L2（IEEE 802.3）

PTP 报文可承载于 UDP/IPv4（L3）或直接承载于以太网帧（L2，EtherType `0x88F7`）。Odin1 Lite 采用 **L2（IEEE 802.3）** 传输：

- L2 报文不经过 IP 协议栈，时延更小、路径确定性更强；
- 需要网络中所有 PTP 端口配置为同一传输协议（本方案交换机端口协议须设置为 IEEE 802.3）。

### 14.1.4 主从选举（BMCA）

网络中的时钟通过**最佳主时钟算法（Best Master Clock Algorithm, BMCA）**依据时钟等级（clockClass）、精度（clockAccuracy）、优先级（Priority1/Priority2）等参数自动选举主时钟。在 Odin1 Lite 的典型部署中，上位机被显式配置为 `masterOnly`，交换机作为边界时钟向上游（Host）同步、向下游（设备）提供时间源。

## 14.2 系统架构

Odin1 Lite 的 PTP 同步体系由三层组成：

```text
┌──────────────────┐
│   Host（主时钟）  │  ptp4l(masterOnly) + phc2sys（系统时钟 → 网卡 PHC）
└────────┬─────────┘
         │ IEEE 802.3（L2 PTP 报文）
┌────────┴─────────┐
│  PTP 交换机（BC） │  HiSync PTP 交换机 R01，P0 = 管理，PTP1~PTP4 = 一主三从
└────────┬─────────┘
         │
┌────────┴─────────┐
│  Odin1 Lite（从） │  ptp4l + phc2sys（网卡 PHC → 系统时钟）+ odin_ptp_daemon
└──────────────────┘
```

| 组件 | 角色 | 说明 |
|:--|:--|:--|
| Host `ptp4l` | 主时钟端口 | `-H`（硬件时间戳）`-2`（L2 传输）`--masterOnly=1` |
| Host `phc2sys` | 时钟驯服 | 将 Host 系统时钟（CLOCK_REALTIME）同步到网卡 PHC |
| PTP 交换机 | 边界时钟（BC） | 上游跟随 Host，下游为最多三台设备提供时间；SYNC 指示灯同步状态可视化 |
| 设备 `ptp4l` / `phc2sys` | 从时钟 | 将网卡 PHC 与主时钟对齐，并把 PHC 同步到设备系统时钟 |
| 设备 `odin_ptp_daemon` | 常驻守护进程 | 管理设备端 PTP 会话，配合驱动时间同步模式 |

## 14.3 网络与交换机配置

Odin1 Lite 通过 **HiSync PTP 交换机（R01 型，北京飞灵科技）** 组建同步网络：

| 项 | 说明 |
|:--|:--|
| 端口定义 | `P0`：连接管理电脑（WebUI 配置，**不参与 PTP**）；`PTP1 ~ PTP4`：一主三从 PTP 端口 |
| WebUI 地址 | `http://192.168.1.82`（需与 Odin1 Lite / Host 同网段） |
| 登录账户 | 用户名 `admin` / 密码 `admin` |
| 指示灯 | `SYNC`：绿灯慢闪 = PHC 未同步；绿灯常亮 = 已与上游 PHC 同步 |

配置步骤：

1. 管理电脑接入 `P0`，将其配置为 `192.168.1.x` 网段，浏览器访问 `http://192.168.1.82` 登录 WebUI；
2. 左侧列表进入「时间同步 → PTP」，点击「端口配置」；
3. 若各 PTP 端口 `Protocol` 列显示的不是 **L2**，点击「编辑」，将 Protocol 更改为 **IEEE 802.3**（其余配置保持默认），保存；
4. 将**所有** PTP 端口协议改为 L2 后，点击「保存并应用」，等待交换机重启。

> 主时钟 Host 与从设备均须接入 `PTP1 ~ PTP4`，不要接入 `P0`。

## 14.4 主机端（Host）配置

前提：确认 Host 网卡支持硬件时间戳（`ethtool -T <网卡>` 输出含 `hardware-raw-clock` / `SOF_TIMESTAMPING_RAW_HARDWARE`），并确认接入交换机的网卡名称（下例为 `enp1s0f0`，请替换为实际网卡）。

```bash
# 启动 ptp4l：L2 传输 + 硬件时间戳 + 仅主模式
sudo ptp4l -i enp1s0f0 -m -H -2 --masterOnly=1

# 启动 phc2sys：将系统时钟同步到网卡 PHC（另一终端）
sudo phc2sys -s CLOCK_REALTIME -c enp1s0f0 -m -O 0 -S 0.001
```

Host 启动后，无论从设备是否接入，交换机都应先与 Host 完成同步——可通过交换机 `SYNC` 指示灯（绿灯常亮）或 WebUI「同步状态」页面（时间同步状态、PTP 时钟时间、偏移量、祖父时钟信息等）确认。

## 14.5 硬件支持性检查与软同步方案

### 14.5.1 如何判断 Host 网卡是否支持 PTP 硬件时间戳

PTP 硬件时间戳依赖网卡的 PHC（PTP Hardware Clock）。在 Host 上依次执行以下检查：

**① 查看网卡时间戳能力**

```bash
ethtool --json -T enp1s0f0     # 或旧版：ethtool -T enp1s0f0
```

| 输出关键字 | 含义 | 结论 |
|:--|:--|:--|
| `hardware-raw-clock: true` / `SOF_TIMESTAMPING_RAW_HARDWARE` 且 `ptp-hardware-clock` 指向 `/dev/ptpN` | 网卡具备独立 PHC | ✅ 支持硬件同步，按 14.4 正常部署 |
| 仅有 `software-raw-clock: true` / `SOF_TIMESTAMPING_SOFTWARE` | 网卡无 PHC | ❌ 不支持硬件同步，转 14.5.2 软同步 |

常见支持硬件时间戳的网卡：Intel i210/i211/i225/i226、82574、82599/X520、X550 系列；大多数消费级板载网卡（如 Realtek RTL8111/8125、部分 Intel 1225-V 系列）**不支持**。

**② 确认 PHC 设备节点**

```bash
ls /dev/ptp*
# 支持硬件时间戳的网卡会枚举出 /dev/ptp0 等节点；
# 可用 ethtool --json -T enp1s0f0 输出中的 ptp-hardware-clock 字段确认对应关系
```

**③ 验证 PHC 可读**

```bash
sudo phc_ctl /dev/ptp0 get
```

若返回当前 PHC 时间则说明硬件时钟工作正常。

> 设备端（Odin1 Lite）已内置 PHC 硬件时钟，上述检查仅针对 Host。若 Host 不支持硬同步，整条链路将退化为软同步精度。

### 14.5.2 软件时间戳方案（无 PHC 网卡）

若 Host 网卡不支持硬件时间戳，仍可使用 linuxptp 的**软时间戳（software timestamping）**模式完成 PTP 同步：报文打戳点从 PHY/MAC 退化为内核协议栈，消除用户态处理时延，但无法消除内核收发路径抖动，典型同步精度从亚微秒级退化为**百微秒级（约 10 μs ~ 1 ms）**。

Host 侧只需一处变化（对比 14.4）：`ptp4l` 的 `-H`（硬件时间戳）改为 `-S`（软件时间戳）：

```bash
# Host：软时间戳主时钟（-S = software timestamping）
sudo ptp4l -i enp1s0f0 -m -S -2 --masterOnly=1

# phc2sys 不再适用（Host 无 PHC）：
# -S 模式下 ptp4l 的时间戳直接来源于系统时钟 CLOCK_REALTIME，
# Host 系统时钟本身就是对外发布的时间基准，无需额外驯服

# 设备端：保持硬件时间戳从模式不变（odin_ptp_daemon / ptp4l -H），无需任何改动
```

说明：设备侧 PHC 始终可用，建议保持硬件时间戳从模式；链路整体精度瓶颈在 Host 软戳一侧。若客户对精度要求较高且 Host 不带 PHC，也可建议客户更换一颗支持硬件时间戳的网卡（如 Intel i226，成本低且主流发行版免驱）。

> **精度预期与选型建议**
>
> | 方案 | Host 硬件要求 | 典型同步精度 | 适用场景 |
> |:--|:--|:--|:--|
> | 硬件 PTP（推荐） | 网卡带 PHC | 亚微秒级 | 多传感器紧耦合融合、运动重建 |
> | 软件 PTP（-S） | 普通网卡 | 10 μs ~ 1 ms | 时间粗对齐、日志对时 |

### 14.5.3 软同步下的替代工具

软同步对 Host 网卡无硬件要求，实现工具也不限于 linuxptp。除本方案默认的 **linuxptp（ptp4l）** 外，主流可选实现如下：

| 工具 | 协议/Profile | 平台 | 特点 | 适用性 |
|:--|:--|:--|:--|:--|
| **linuxptp**（ptp4l + phc2sys） | IEEE 1588-2019 全配置（含 L2/UDP、802.1AS） | Linux | 官方内核配套实现，功能最全，软/硬时间戳均支持 | ✅ 推荐，本文档默认方案 |
| **ptpd2**（PTPd） | IEEE 1588-2008 | Linux/BSD | 老牌实现，配置简单，社区活跃度已下降 | ⚠️ 可用，无新特性，不建议新项目采用 |
| **OpenAvnu gPTP** | IEEE 802.1AS（gPTP） | Linux/Windows | Intel 主导，面向 AVB/TSN 音视频场景，Windows 侧可用 | ⚠️ 仅推荐 gPTP/TSN 场景 |

说明：

1. **802.1AS（gPTP）注意**：若客户环境是车载/AVB/TSN 网络并使用 gPTP profile，需确认 PTP 交换机同样支持 802.1AS，且 Odin1 Lite 侧 daemon 是否兼容对应 profile，请先联系留形技术支持确认；
2. **ptpd2 与 ptp4l 不能同时运行**在同一主机，端口会冲突；
3. 无论选择哪种工具，软同步的精度上限由**打戳点位置**（内核协议栈）决定，而非工具本身，各工具在相同软戳模式下精度基本相当。

## 14.6 设备端配置

设备端 PTP 会话由固件内置的 `odin_ptp_daemon` 守护进程自动管理（与 `ptp4l` / `phc2sys` 配套），**无需用户登录设备做任何手工操作**。

用户的全部操作都在 Host 侧通过 ROS 服务完成：

驱动提供时间同步模式服务（详见 [5. 数据输出](5.%20Data%20output_)）：

```bash
# 查询当前同步模式（0=SysTick 系统时钟，1=PTP）
ros2 service call /manifold/device0/get_sync_mode \
  odin_ros_driver_rev1/srv/GetSyncMode "{}"

# 切换到 PTP 硬件时间戳模式（需重启设备后生效）
ros2 service call /manifold/device0/set_sync_mode \
  odin_ros_driver_rev1/srv/SetSyncMode "{sync_mode: 1}"
```

PTP 生效后，可实时查询同步质量：

```bash
ros2 service call /manifold/device0/get_ptp_sync_status \
  odin_ros_driver_rev1/srv/GetPtpSyncStatus "{}"
```

返回的快照包含同步状态、时钟偏移（offset from master）、链路时延（mean path delay）与频率调整量等，可用于量化评估同步精度。

> 若 `get_ptp_sync_status` 长时间显示未同步，请按顺序排查：交换机端口协议是否为 L2（14.3）→ Host 主时钟是否运行（14.4）→ 设备时间同步模式是否为 PTP（14.6）；仍无法解决请联系留形技术支持。

## 14.7 同步验证

1. **交换机同步状态**：`SYNC` 指示灯绿灯常亮，WebUI「同步状态」显示已同步且偏移量在毫秒级以内；
2. **PTP 同步状态查询**：通过 `get_ptp_sync_status` 确认设备侧同步状态与偏移量（见 14.6）；
3. **数据时间戳验证**：Host 运行驱动后，检查传感器话题时间戳已切换到同步后的时钟：

```bash
ros2 launch odin_ros_driver_rev1 odin1Lite.launch.py
ros2 topic echo /manifold/device0/imu --field header.stamp
```

## 14.8 注意事项

1. 全网络 PTP 端口必须统一使用 **L2（IEEE 802.3）** 协议，混用 UDPv4 会导致无法同步；软同步模式下报文同样走 L2，交换机端口配置要求不变；
2. `set_sync_mode` 修改后**必须重启设备**才能生效；
3. 设备端 `odin_ptp_daemon` 与系统默认 `ptp4l` / `phc2sys` 互斥，同时运行会导致同步异常；
4. Host 网卡最好支持硬件时间戳；不支持时可退化为软时间戳（`ptp4l -S`），但同步精度将显著下降（详见 14.5）；
5. PTP 交换机与 Host、设备须处于同一网段，Host 接入交换机 `PTP1 ~ PTP4`，管理电脑接入 `P0`；
6. 建议通过 `get_ptp_sync_status` 定期监控偏移量，偏移持续增大时优先排查链路、交换机端口配置与 Host 主时钟状态。
