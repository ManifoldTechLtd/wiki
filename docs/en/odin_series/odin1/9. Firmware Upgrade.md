## Firmware Release Notes

This release focuses on self-recovery of the localization algorithm and camera exposure control: the localization algorithm now restarts automatically after a map switch, and the maximum exposure time can be adjusted remotely. Sensor acquisition is decoupled from algorithm computation, depth point-cloud intensity reporting is corrected, large file transfers are faster, and an automatic recovery mechanism is added for abnormal conditions. Several stability issues are also fixed, including repeated start/stop commands, mismatched start/stop responses, and stop timeouts. This update also upgrades the MCU, so the upgrade takes longer than before.

### New Features

1. **Localization algorithm restarts automatically after a map switch**

   After the host switches the map mode or updates the relocalization map file, the localization and mapping algorithm restarts automatically and keeps working. No manual device reboot or re-issued start command is required.

2. **Maximum exposure adjustable remotely**

   The host can query the current exposure route and dynamically set the maximum exposure time. The device validates the requested limit against the current frame-rate tier; out-of-range requests receive an explicit rejection instead of silently taking effect.

### Improvements

1. **Smarter exposure control**

   When the image stream is enabled, the device automatically applies a tuned default maximum exposure for the current frame-rate tier, striking a better balance between nighttime brightness and motion blur. The exposure limit of each frame-rate tier has been re-calibrated, and failed exposure settings now report a failure status instead of being reported as successful.

2. **More continuous image and IMU data**

   Sensor data acquisition and localization/mapping computation are now decoupled, so fluctuations in algorithm-side workload or algorithm restarts no longer interrupt the image and IMU data received by the host.

3. **More accurate depth point-cloud intensity**

   The depth camera SDK is upgraded so that point-cloud intensity is reported in a more accurate and consistent way, preventing points from being incorrectly discarded during intensity filtering.

4. **Faster large file transfer**

   Receiving large files such as maps sent from the host is noticeably faster.

5. **Self-recovery after exceptions**

   In rare cases the device could become unresponsive and require a manual restart. On an exception the device now exits and restarts itself automatically, and the host can keep issuing commands normally, reducing on-site manual intervention.

### Bug Fixes

1. **Repeated or concurrent start/stop commands no longer cause state errors**

   When the host sends repeated or interleaved start/stop commands, the device no longer runs the multi-second stop procedure repeatedly, and start/stop states no longer overwrite each other.

2. **Start/stop responses match their own commands**

   Every start or stop returns its own response; stop responses are no longer swallowed and success is no longer reported spuriously.

3. **Stop timeouts converge automatically**

   If the running algorithm process does not exit within the timeout, it is forcibly terminated so that the next start can always re-establish the data link, leaving no residual instance on the device.

4. **No more hangs or stale data during stop and re-link**

   Data reading is interrupted first during the stop procedure, and the data channel is exclusively occupied before re-establishing the link, so stale frames from the previous round are no longer reported as new data.

5. **No more occasional hangs when stopping the localization algorithm**

   The release order of multi-threaded shared resources in the stop procedure is optimized, eliminating device unresponsiveness caused by lock-handling exceptions.

6. **Repeated start commands no longer spawn duplicate algorithms**

   Only one instance of the localization and mapping algorithm runs no matter how many start commands are issued.

### Compatibility Notes

This release contains no breaking changes and the host interface requires no additional adaptation.

## Upgrade Notes

- This firmware requires driver version **0.13.0** or later.
- Recommended driver version: **0.14.5**.
- This update also upgrades the MCU, so the upgrade takes longer than before; please be patient and never disconnect power during the upgrade.
- This firmware release contains no breaking changes and requires no additional migration.

## ROS Driver Release Notes

Driver repository: <https://github.com/manifoldsdk/odin_ros_driver.git>

Current version: 0.14.5 (minimum requirement 0.13.0)

1. Added the maximum exposure interface: `ae_max_exposure_time` (AE exposure upper limit, ms) in `control_command.yaml`, plus the `/odin1/set_ae_max_exposure` service (ROS1 / ROS2).
2. Fixed driver crashes caused by USB hotplug.
3. Updated the SDK: when the exposure limit exceeds the per-tier default (30 / 20 / 15 ms at 10.26 / 14.47 / 28.92 Hz), a warning is printed but the request is still sent.
4. Updated the SDK: when the device is already in the requested state, `lidar_open_device` / `lidar_close_device` / `lidar_set_mode` / `lidar_start_stream` / `lidar_stop_stream` are skipped (warning printed, 0 returned), avoiding repeated start/stop procedures.

## Upgrade Procedure

📄 [Download detailed Firmware Upgrade Tool instructions (PDF)]({{ '/odin_series/odin1/assets/pdf/Odin1_Firmware_Update_Tool_User_Guide.pdf' | relative_url }})

> ℹ️ Upgrade tool versions:
> - The 0.14.3 and later firmware packages bundle upgrade tool **0.6.0** (compatible with all firmware versions) and the `update.sh` one-click upgrade script.
> - `update.sh` auto-detects the host architecture (amd64 / aarch64) and tries tools 0.6.0 → 0.5.0 → 0.4.9 in order.
> - Historical rule: firmware ≤ 0.12.4 → tool **0.4.9**; firmware ≥ 0.13.0 → tool **0.5.0**.

**Before upgrading:**

- Stop the ROS driver and reboot the device before upgrading.
- Do not disconnect power during the upgrade; this update includes the MCU upgrade, and a power loss in the middle may leave the device unable to boot properly.
- A USB 3.0 port is recommended; USB 2.0 also works, but disconnections may occur during the upgrade and require restarting the upgrade.
- After the upgrade, fully power off the device and then power it on again.
- Use the latest `odin_ros_driver` after the upgrade.

1. Download and extract the firmware package from the link above.
2. Enter the extracted directory and run the one-click upgrade script:

```shell
./update.sh
```

3. Alternatively, specify the firmware package and tool version manually:

```shell
# Example for an x86 platform
./odin1_firmware_update_tool_0.6.0_amd64 odin1_firmware_update_0.14.7.tar.gz
```

Wait for the upgrade to complete; the device will reboot automatically.
