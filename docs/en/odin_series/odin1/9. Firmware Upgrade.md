## Firmware Release Notes

### Improvements

1. **Optimized USB transfer scheduling under high-load conditions**

   When high-bandwidth streams such as depth point clouds are running at full capacity, command, heartbeat, and file-transfer channels are now prioritized to ensure timely responses and prevent control delays caused by bandwidth contention.

2. **Enhanced automatic recovery after device reconnection**

   After the device reconnects to the host, all data channels recover automatically without requiring a device reboot or manual intervention, improving fault tolerance in field deployments.

3. **Improved file-transfer stability**

   File-transfer tasks such as map saving now have a timeout-protection mechanism that terminates or retries the task promptly on failure, preventing indefinite hangs.

### Bug Fixes

1. **Fixed a potentially unrecoverable disconnection under USB 2.0 high-load conditions**

   Previously, when bandwidth was near saturation, the device could disconnect and the host could not re-detect it without rebooting the device. Stable connection is now maintained even under extreme bandwidth conditions.

2. **Fixed depth-stream display freezing under high-load conditions**

   Previously, when multiple streams were transmitting simultaneously, some depth frames could be incomplete, causing point-cloud display to stop updating for extended periods. Frame integrity is now guaranteed, improving stability for SLAM and similar applications.

3. **Fixed gradual resource accumulation after repeated device reconnections**

   Improves long-running stability of the device.

4. **Fixed file-transfer tasks getting stuck**

   Previously, tasks such as map saving could hang and never complete. Tasks now complete reliably and retry promptly on failure.

5. **Fixed sensor timestamp accuracy in specific scenarios**

   Improves time-synchronization accuracy across multiple sensors, enhancing data quality for SLAM fusion and similar applications.

6. **Optimized OTA upgrade speed**

   Streamlined OTA upgrade process significantly reduces the time required to complete an upgrade.

## Upgrade Notes

- The communication protocol between the device and the host SDK has been updated.
- Be sure to upgrade the device firmware and the host-side SDK / driver at the same time.
- A version mismatch between the device and the host can cause unstable connections and abnormal communication.
- This firmware requires driver version **0.13.0** or later.

## Upgrade Procedure

📄 [Download detailed Firmware Upgrade Tool instructions (PDF)]({{ '/odin_series/odin1/assets/pdf/odin1固件升级工具使用说明.pdf' | relative_url }})

> ℹ️ Starting from firmware 0.13.0, the upgrade protocol has changed:
> - Current firmware ≤ 0.12.4 → use upgrade tool version **0.4.9**
> - Current firmware ≥ 0.13.0 → use upgrade tool version **0.5.0**

**Note: Do not run the driver during the upgrade, and do not power off during the process. A USB 3.0 port is recommended; USB 2.0 also works, but disconnections may occur during the upgrade and require restarting the upgrade with Ctrl+C.**

1. Download the firmware via the link above.
2. Extract the archive.
3. Run the upgrade script (the upgrade tool is available with two suffixes: `amd64` for x86 platforms and `aarch64` for ARM platforms — pick the one that matches your platform):

```shell
# Example for an x86 platform
./odin1_firmware_update_tool_0.5.0_amd64 odin1_firmware_update_0.14.1.tar.gz
```

Wait for the upgrade to complete; the device will reboot automatically.
